# Правила работы в репозитории CrewHarness

## Канон

Этот файл — часть **Канона**: всего, где записаны правила разработки проекта. Начинать — с его входного файла
[doc/canon/README.md](doc/canon/README.md): оттуда ссылками подтягиваются все части Канона.

Для ИИ-агентов и людей, которые правят этот репозиторий. **Основа — методика
[unitcraft/ai-dev-methodology](https://github.com/unitcraft/ai-dev-methodology/tree/main)**; её правила здесь не
пересказываются. Чем проект от неё отличается — [doc/canon/process.md](doc/canon/process.md); решения —
[doc/canon/decisions/](doc/canon/decisions/README.md). Ниже — только правила этого репозитория и этой машины; у каждого сказано,
что без него ломается.

## Порядок работы

1. **Задачи — в `doc/tasks/NNN-<slug>/`**, цикл сессий методики; план — `plan.md` в папке задачи, в Канон не
   переносится; большая работа — эпик из задач ([process.md](doc/canon/process.md)). Планы 001–006 — архив, не правятся.
2. **Слово владельца записывается с датой и источником** («владелец, 2026-10-07»), а не пересказом — правило и причина в методике ([`task-sessions.md`](https://github.com/unitcraft/ai-dev-methodology/blob/main/task-sessions.md), «Правила»).

## Git

3. Изменения — в отдельном рабочем дереве на своей ветке (механизма нет: каталог работы агента хуки не видят;
   судится приёмкой — Сессия С6 по diff и владелец на воротах); в `main` — только `git merge --ff-only` (механизм:
   защита ветки `main` на GitHub, линейная история). *Почему:* рабочая копия `main` у владельца — живая, её файлы
   загружает работающий сервис (п. 11).
4. Коммиты: сообщение по-английски; `git commit -s`; без трейлеров соавторства (механизм: страж сообщения, вызывает
   `commit-msg`, `pre-push`, CI); файлы — перечнем в самой команде коммита (`--only`/`-o`, `--include`/`-i` или
   ` -- <файлы>`); `git add -- <файлы>` — только чтобы git узнал новый файл; никогда `git add -A` / `git add .` — в
   коммит попадают чужие и временные файлы (механизм: хук агента — подсказка, не барьер); без упоминаний
   инструментов (механизма нет: страж не берётся).
5. Никогда не `push --force` (механизм: защита ветки `main` на GitHub; для веток задач — подсказка хука агента). Пуш —
   только после зелёных тестов, п. 8 (судится приёмкой: Сессия С6 перепрогоняет тесты, владелец — на воротах сдачи).
   **В пуш входят только свои коммиты** (владелец, 2026-10-10: «ты обязан заливать только свои файлы»): ветку для пуша строят от
   `origin/main`, а не от локального `main`, где бывают чужие непушенные коммиты других окон; перед пушем — `git fetch` и
   `git log origin/main..main`; свой коммит уходит как `git push origin <коммит>:main`, а если он стоит поверх чужих
   непушенных — остановиться и спросить владельца (механизма нет: подсказка этого пункта; хук агента `git push origin main` не
   отличает свои коммиты от чужих). *Почему:* 2026-10-10 пуш `main` увёл в публичный репозиторий два чужих коммита плагина, а
   откатить без силового пуша (п. 5) нельзя.
6. Ветки и рабочие деревья после слияния удаляются, включая пустые папки деревьев (механизма нет: уборка — вне
   задачи).

## Стражи

Правила с пометкой «механизм» держит код в `scripts/`; пометка стоит только там, где механизм правда есть.

- Установка хуков git — один раз на репозиторий: `sh scripts/install-hooks.sh` (ставит `core.hooksPath` =
  `scripts/githooks` и ожидаемый адрес автора из `git config user.email`; повтор ничего не меняет). Настройка общая для
  всех рабочих деревьев: в дереве на ветке без папки `scripts/githooks` хуки молча не работают, такую ветку обновляют
  ребейзом на `main`.
- Список запрещённых имён лежит вне репозитория: `~/.config/crew-harness/private-names.txt` (образец на строку, `#` —
  комментарий; путь переопределяет `CREW_PRIVATE_NAMES_FILE`), в CI — секрет `CREW_PRIVATE_NAMES`. Секрет и защиту
  ветки `main` заводит `scripts/github-setup.sh` (`secret`, `protect`) — только по слову владельца. Нет списка —
  страж красный, а не молчит.
- Команды (из корня дерева): все стражи дерева — `sh scripts/guards/run-all.sh` (`--index` — по индексу); секреты и
  пути машины — `python scripts/guards/guard-secrets.py --tree` (`--index`, `--commit <хеш>`); сообщение —
  `python scripts/guards/guard-commit-message.py --commit <хеш>`; подключение стражей —
  `python scripts/guards/check-wiring.py`.
- Самотесты: `sh scripts/guards/selftest/run-selftests.sh`, один — `python scripts/guards/selftest/test-<имя>.py`;
  «доказательство красного» — `sh scripts/guards/prove-red.sh`; пустой корень — `sh scripts/guards/probe-empty-root.sh`.
  Они тяжёлые: по одному, с паузами (п. 9).
- Стражи — до пуша, а не барьер: хуки git обходятся `--no-verify`, хук агента не видит псевдонимы и вложенные
  оболочки; CI проверяет то же после пуша. Нашёл нарушение — исправь текст, а не обходи страж.

## Тесты и машина

7. Тесты частей: `opencode-plugin` — `npm test` (37 файлов) из `opencode-plugin/`.
8. Перед пушем — весь набор тестов затронутой части. Пуш с красным набором — нарушение, даже «на минутку»
   (судится приёмкой: Сессия С6 перепрогоняет тесты, владелец — на воротах сдачи).
9. **Машина владельца нагружена** (гейты проектов, десятки сессий агентов): весь набор одним прогоном подвешивает
   живой сервис, и окна перезапускают его сами (2026-10-07: три перезапуска за восемь минут, даже с низким
   приоритетом). Под нагрузкой — тесты по одному с паузами; во время разработки — только затронутые.
10. Тяжёлые команды проектов (гейты, сборки, полные прогоны) — только через очередь машины, не напрямую.

## Живая система

11. Рабочая копия `main` (`opencode-plugin/`) подгружается работающим сервисом OpenCode на лету: правка файлов в ней —
    правка живой системы. Править — только в рабочем дереве (п. 3).
12. Сервис перезапускает только владелец. Изменение, которому нужен перезапуск (пути, переименования, переносы, код
    провайдера), готовится целиком; владелец предупреждается заранее; обновление основной копии — по его слову «обновляй».
    Перед перезапуском — предупредить интегратора проекта и дождаться «готово к перезапуску».
    Порядок (проверено 2026-10-10): по слову «обновляй» оркестратор обновляет основную копию `main` (`git update-ref`
    и `git restore --source=<коммит> --staged --worktree -- opencode-plugin doc`, без `reset` и `stash`; локальный файл
    настроек владельца не трогается) и сообщает «обновлено»; владелец сразу закрывает окна `opencode`, останавливает
    процесс службы (`Get-CimInstance Win32_Process -Filter "Name='opencode.exe'"`, отбор по `serve --service`,
    `Stop-Process`), убеждается, что процессов `opencode` не осталось, и запускает окна проектов их скриптами (первое
    окно поднимает службу, остальные подключаются); после перезапуска владелец пишет «перезапустил», оркестратор проверяет журнал плагина и `crew_doctor`. Слово «обновляй» разрешает обновить основную копию, перезапуск остаётся за владельцем (слово владельца, 2026-10-11: «неудачное слово переключай»). Обновление
    файлов само подгружает плагин на лету (п. 11), поэтому между «обновлено» и перезапуском пауза не делается.
13. Папку, в которой стоит процесс (наблюдение, вкладка сессии, слежка сервиса за файлами), Windows не удаляет и не
    переносит: сначала освободить (закрыть вкладки, остановить сервис), потом трогать.
14. Не должно быть ручных команд там, где их может сделать программа: владелец не набирает команды за агента.

## Публичность

15. Репозиторий публичный ([ADR-0006](doc/canon/decisions/ADR-0006-public-repository.md)): ни локальных путей машины
    владельца, ни имён приватных репозиториев, ни учётных данных; из репозиториев и проектов владельца упоминаются только публичные репозитории https://github.com/nv-lang и https://github.com/unitcraft — другие не называются вовсе, даже в правиле о том, что их нельзя называть — в коде, документах, папках задач и
    сообщениях коммитов. Примеры путей — общие (`C:/work/...`). Язык Нова — только https://github.com/nv-lang/nova.
    Руками искать не нужно: путь машины, секрет и имена из списка владельца ловят стражи (`guard-secrets.py`,
    `check-private-names.py`; механизм: стражи приватности, вызывают `pre-commit`, `commit-msg`, `pre-push`, CI — файлы
    по ним, сообщения коммитов — страж сообщения). *Почему:* историю без силового пуша не вычистить, а он запрещён
    (п. 5).

## Чужие репозитории

## Общение с владельцем

17. По-русски; коротко; сначала ответ, потом подробности. Каждый вопрос владельцу — с рекомендацией ответа и доводом
    ([process.md](doc/canon/process.md)). Сделанное и проверенное — без оговорок; не сделанное — так
    и сказать.
18. Перед переименованием, переносом и любым действием, которое меняет живую систему, — предупредить и дождаться
    согласия.
