# Задание: вопрос владельцу как инструмент плагина (`crew_question`) и надёжный признак «ждёт вас»

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-11.
Источник: предложение владельца 2026-10-11 и наблюдение: интегратор проекта-потребителя ждала слова владельца фразой без вопроса, владелец этого не увидел.

Задача полная: разбор, план, реализация, сдача.

## Что установлено поиском (2026-10-11; документация и описания OpenCode, версия на машине 2.0.26 — свериться)

- Встроенный вопросник OpenCode — инструмент `question` (вход: массив вопросов; у вопроса `question`, `header`, `options` с `label` и `description`, `multiple`, `custom`); сервер хранит ожидающий запрос в памяти и блокирует ход сессии, пока клиент не ответит. Создаёт запрос только вызов инструмента моделью; инструмент регистрируется для клиентов app, cli, desktop.
- Документация плагинов описывает собственные инструменты плагина (`description`, `args`, `execute(args, context)`; в `context` документированы только `directory` и `worktree`) и говорит, что плагинный инструмент с тем же именем, что у встроенного, имеет приоритет. Способа вызвать встроенный вопросник из плагина, метода `ask` у контекста инструмента и методов SDK для вопросов документация не называет.
- По описаниям исходного кода сервер имеет маршруты `GET /question` (список ожидающих), `POST /question/{id}/reply` (ответ: массив ответов на каждый вопрос) и `POST /question/{id}/reject`; события вопросов не идут в поток событий, клиент видит вызов инструмента `question` в состоянии выполнения. В документации SDK этих методов нет. Для версии 2.0.26 проверить, что маршруты есть и работают.

## Что есть сейчас

- Признак «ждёт вас» ставится по тексту последнего сообщения хода (`endsWithQuestion`, `status.ts`: знак «?» или фраза ожидания). Открытый встроенный вопрос сам признака не ставит.
- Согласование планов уже показывает решение в окне и получает ответ файлом (`approvals.ts`, `tui.ts`): образец «инструмент плагина ждёт файл ответа из окна».
- Режим автоответа (`answer_mode`) разбирает прозу вопроса по сетке слов; структурированного вопроса у него нет.

## Что нужно

- Решить способ и назвать инструмент. Рекомендация оркестратора: `crew_question` (один вызов — один вопрос с полями: текст, тип (`requirements`, `plan`, `implementation`, `gate`), рекомендация (первым вариантом), варианты с пояснением, `multiple`, `custom`), потому что режим автоответа ведёт запись на вопрос; несколько вопросов — несколько вызовов. Форма с массивом (`crew_questions`) — только если разбор покажет, что встроенный формат нужно повторить полностью.
- Способ показа человеку, по порядку проверки в разборе:
  1. Читать встроенный вопросник как наблюдатель: плагин через `GET /question` (если маршрут есть в 2.0.26) видит открытые встроенные вопросы и ставит признак «ждёт вас», счётчик, повтор по `owner_reminder_min`; при режиме автоответа может ответить через `POST /question/{id}/reply` по рекомендации (типы `gate` и слова ворот — никогда).
  2. Собственный диалог в окне по образцу согласования планов: `crew_question` пишет вопрос в каталог данных, окно показывает варианты, ответ приходит файлом, инструмент возвращает его агенту; не зависит от внутренностей OpenCode и переносится в собственную консоль.
  3. Подмена встроенного `question` одноимённым плагинным инструментом — только если без неё нельзя, с описанием рисков (теряется родной интерфейс).
- Запись вопроса: идентификатор, роль, время, тип, рекомендация, статус (ожидает, отвечен, снят); ставит признак «ждёт вас» и обязательство. Правило для ролей: ожидание слова владельца оформляется вопросом с рекомендацией (справка `crew_help` одним предложением).
- Тесты по одному, с паузами ([AGENTS.md](../../../../AGENTS.md)); красная проверка до правки.
