# Разбор задачи 020 (быстрый путь, одобрено владельцем 2026-10-11)

## Откуда приёмщик берёт `machine: true`

Источник в плагине установлен: текст для MCP-клиентов в `opencode-plugin/mcp.ts` (строка про `crew_watch`) говорил
«гейт, сборку и полный прогон тестов ставь с `machine: true`», а справка `crew_help` и описание параметра в `core.ts`
называли «команду, которая грузит машину» (гейт, сборка, прогон тестов), но не говорили, что ожидание удалённого CI
идёт без неё. Ожидание CI в проекте часто оформляют как «гейт» — отсюда `true`. Тексты ролей в плагине (`crew_role`)
про `machine` не говорят. Правило приёмки чужого проекта (nova) не читалось и не правится (границы задачи): если оно
велит `true` для ожидания CI — это находка для письма их интегратору.

## Решение: справка, а не автоматическое различение

Различать автоматически (по `heavy_commands` или признаку в команде) не нужно. Довод: ожидание — произвольная
оболочная команда (`gh`, `check-push-proven-by-ci`, `until ...; sleep 20`); надёжного признака «не грузит машину» у
неё нет, а список «лёгких» команд пришлось бы вести в каждом проекте. Обратное направление уже автоматическое:
`heavy_commands` отправляет тяжёлую команду в очередь и без `machine: true`. Значит, достаточно правила для того, кто
ставит наблюдение: `true` — только тяжёлым, остальное — `false`. Правило добавлено в `crew_help`, описание
`machine` в `crew_watch`, README плагина и текст `mcp.ts`; тест справки проверяет его, снимок обновлён.

## Как плагин показывает держателя места и есть ли срок

Факты по коду (изменений кода очереди нет):

- Держателя места плагин **не называет**. `crew_watch` без команды (`core.ts`) и `/crew` (`status.ts`, `в очереди машины
  с HH:MM`) показывают только наблюдения своей вкладки; ждущему сообщают число идущих перед ним (`перед ней N`),
  но не чьё наблюдение держит место и с какого времени. Увидеть держателя можно только по записям очереди
  (файлы наблюдений в каталоге данных плагина). Это зазор: остановку вроде 19-минутной видно лишь тому, кто читает записи.
- Отдельного срока у места **нет**. Срок — предел наблюдения `minutes` (по умолчанию 120, не больше 720), он считается
  от запуска; по его истечении процесс останавливается (код 124) и место освобождается (`watch.ts`, `pollWatches`).
  Значит, держатель с ожиданием CI может занимать единственное место до 12 часов. Освободить раньше —
  `crew_watch {action: "cancel", id}` (владелец наблюдения).
- Возможное продолжение (вне быстрого пути, нужно слово владельца): показать в `/crew` и в ответе `crew_watch`
  держателя места (id, заметка, вкладка, с какого времени) и отдельный срок места короче предела наблюдения.
