# Разбор задачи 030 (быстрый путь)

- **«Пересобран» или «устарел».** При завершении precheck плагин запоминает вершину ветки задачи (`precheck.branch_tip`). При merge,
  если вершина ветки изменилась с тех пор, она должна быть предком кандидата (`merge-base --is-ancestor`) либо иметь то же дерево
  (`rev-parse <ветка>^{tree}`, случай squash); иначе запись устаревает («ветка задачи ушла вперёд кандидата»), замок не выдаётся,
  ответ называет короткие SHA ветки и кандидата и просит пересобрать кандидата и повторить CI и precheck.
- **Почему сверка только при сдвиге вершины.** Кандидата без ветки и с другим деревом приёмщик собирает сознательно (его и так
  предупреждает `finishPrecheck`; сценарии задачи 028 «differs» остаются зелёными). Устаревание — это именно движение ветки после фиксации.
- **Ветки локально нет** (`t.branch` пуст, не разрешается, записи без `branch_tip`): молча пропускаем, не отказываем.
- **accept:** отдельной проверки не добавлено, предупреждение `acceptWarning` уже есть, а merge без свежего кандидата не пропускает.
- **Письмо после rework:** в `reworkLetter` добавлена одна фраза (кандидат устареет, приёмщик пересоберёт от новой вершины) — только когда
  у задачи была запись с кандидатом, не для синхронизации и не для плана. Справка не менялась.
