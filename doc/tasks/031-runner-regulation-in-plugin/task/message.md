Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-11.
Источник: [раннер методики](https://github.com/unitcraft/ai-dev-methodology/blob/main/task-runner.md) (алгоритм «run_task», «Машинные форматы», `state.json`).

## Что есть сейчас

- Раннер описан в методике текстом и псевдокодом; цикл сессий ведёт оркестратор вручную и пропускает шаги (проверка реализации, ворота, файл состояния, потолки заходов).
- Задача 013 готовит ядро раннера на Нове для будущего отдельного сервиса (эпик 001): чистые функции, тесты-сценарии данными (JSON). Нова пока не даёт возможностей для оболочки.
- Плагин `opencode-plugin/` работает уже сейчас и может вести цикл программно.

## Что нужно

- **Регламент как данные:** файл JSONC с графом фаз (РАЗБОР, ПЛАН, РЕАЛИЗАЦИЯ, СДАЧА, ОБРАТНАЯ_СВЯЗЬ), сессий (С1…С9, КОММИТ, ПУШ), ворот (В1…В13), переходов и счётчиков. Подробные описания узлов и переходов — комментариями. Закрепление методики — **полем** (репозиторий и коммит; дубль в комментарии шапки): страж проверяет, что регламент соответствует закреплённой версии `task-runner.md` и таблице «Машинные форматы».
- **Предикаты — в коде, по именам:** «чистая серия», «потолок заходов», «остановка: вопрос/план/…» — фиксированный набор функций; универсального языка условий нет.
- **Исполнитель в плагине:** шаг `step(state, event) → (state′, действия)`; состояние на диске (аналог `state.json`, запись атомарная: временный файл и переименование) перед запросом и перед воротами; **продолжение после перезапуска приложения**: оборванная сессия повторяется или открываются ворота.
- **Прыжок на любой шаг:** событие `jump` только от владельца, с записью в журнал (слово владельца и дата); счётчики (заходы, `pass_origin`, чистая серия) сбрасываются явно, а не молча; пропущенные ворота помечаются «пропущены по слову владельца».
- **Один формат с 013:** тесты-сценарии «состояние + событие → состояние и действия» — обычным JSON, чтобы позже ядро на Нове прошло те же сценарии. Комментарии из JSONC снимаются при сборке для Новы либо ядро читает очищенную копию.
- Тесты по одному, с паузами ([AGENTS.md](../../../../AGENTS.md)); красная проверка до правки.
