# Задание: плагин не должен бесконечно плодить файлы в каталоге данных

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness`. Репозиторий кода: https://github.com/unitcraft/crew-harness (ветка `main`). Дата: 2026-10-11. Быстрый путь по слову владельца.

## Слова владельца (2026-10-11)

- «плагин генерит много файлов, количество которых постоянно растет, ты с этим разобрался?»
- «по рекомендации» — на рекомендацию оркестратора: уборка по сроку, с защитой живого.

## Что есть

Замер каталога данных плагина за пять суток: `read/` — 4479 файлов в 175 папках сессий (19,8 МБ); `inbox/` — 169 пустых папок; `cards/` — 187 карточек (по одной на каждую когда-либо бывшую сессию); `status/` мелкий. Прежняя уборка (`housekeeping.ts`) чистит только письма и только по сроку, пустые папки, карточки и статусы не трогает; наблюдения `watches/` чистятся через 24 ч.

## Что нужно

- Параметр плагина `retention_days` (умолчание 7, 0 — не убирать).
- Раз в сутки: доставленные письма `read/` старше срока, пустые папки сессий в `read/` и `inbox/`, карточки `cards/` и записи `status/` закрытых вкладок.
- Никогда: письмо с открытым вопросом, `inbox/`, карточка и статус открытой вкладки, вкладки с обязательствами или открытой задачей, `tasks/`.
- Проход ограничен числом удалений за вызов; в журнал — одна строка «уборка: убрано писем N, папок M, карточек K».

## Границы

- Только плагин `opencode-plugin/` и документы; реальный каталог данных тестами не трогается.
- Служба перезапускается только владельцем ([AGENTS.md](../../../../AGENTS.md), п. 12).
