# Разбор задачи 023 (быстрый путь)

## Ответы на вопросы задания

- **Видит ли плагин `git worktree add` и `git branch` сессий?** Нет. Сессии вызывают git сами (оболочка), плагин видит только свои инструменты и состояние git при проверке. Поэтому автозапись возможна только по тому, что плагин находит в git сам (`integrate/t<N>`, `integrate/t<N>-*`, деревья на них), в моменты `precheck` (завершение), `accept` и `cleaned`; всё остальное — команда `track`.
- **Как сверять «создано во время задачи».** В этой версии не сверяется: ветка или дерево со старым именем, которое не записано и не подходит под шаблон, не отличимо от чужого. Возможные признаки (время коммита вершины ветки позже создания задачи, родитель на `merge-base` с веткой задачи, `git reflog`) ненадёжны на общей машине с параллельными окнами и могут уронить чужую работу, поэтому не взяты. Сверка заменена явной записью (`track`) и прежним шаблоном как запасным путём.
- **Старые записи без поля.** Поле необязательное, читается как пусто, миграции нет; `cleaned` старой записи работает как раньше (тест TR-1).

## Решения

- Поле названо `side`, а не `extra`: `extra` в записи уже занято дополнительными полями проекта (`task_extra_fields`).
- `cleaned` теперь сам убирает записанное: сначала деревья (кроме `keep`), затем ветки; без `--force`, грязное дерево называется в отказе. Удаляются только локальные ветки; ветки на `origin` по-прежнему проверяются прежним способом (`cleanup: local+remote`).
- Автозапись `integrate/t<N>*` значит, что `cleaned` убирает их без отдельной команды. Тест `crew-review` обновлён: раньше отказ называл `integrate/t1` среди остатков, теперь он сообщает «Убрано по записи задачи».
- Незаписанное и не под `integrate/t<N>`, но найденное шаблоном: отказ как раньше, текст предлагает `track`.

## Не сделано

- Отчёт «незарегистрированное» при `accept` отдельным списком (находка по шаблону и так попадает в отказ `cleaned` и напоминание об остатках; признака «создано во время задачи» нет, см. выше).
- Удаление записанных веток на `origin`.
- Свежее наблюдение (2026-10-11, проект-потребитель): предпроверка создала ветки `integrate/t15-precheck` и `integrate/t15-precheck-main` и деревья `<проект>-15-precheck`, `-precheck-main`; в записи их не было, `cleaned` отказал, удалять пришлось по отдельному слову владельца. Теперь такие имена записываются автоматически.
