# Задание: `crew_doctor` предупреждает, что настройки проекта в рабочей копии расходятся с целевой веткой

Заказчик и владелец: владелец репозитория `unitcraft/crew-harness` (он же отвечает на вопросы и принимает результат).
Репозиторий кода: `unitcraft/crew-harness` (https://github.com/unitcraft/crew-harness, ветка `main`). Дата задания: 2026-10-11.
Источник: наблюдение 2026-10-11 в проекте-потребителе: владелец ожидал для задачи более лёгкую модель (`tier_max: light` лежал в файле настроек рабочей копии), а плагин взял ступень `medium`, потому что читает настройки с целевой ветки, где этого ключа ещё нет.

Задача полная: разбор, план, реализация, сдача.

## Чего хочет владелец (его слова, 2026-10-11)

- «почему на GPT-6.1 Sol? должны на Luna» и «по рекомендации» (завести задачу на предупреждение в `crew_doctor`).
- «оставить чтение с ветки - ОК, но предупреждение должно выводиться на экран постоянно» (владелец, 2026-10-11): настройки по-прежнему читаются с целевой ветки; предупреждение о расхождении видно постоянно, а не только по запросу `crew_doctor`.

## Что есть сейчас

- Настройки проекта (`.opencode/crew-harness.json`) плагин читает с целевой ветки (`origin/<ветка>`, затем локальная); правка файла в рабочей копии до коммита и слияния не действует.
- Расхождение между файлом рабочей копии и веткой нигде не показывается: владелец видит неожиданный результат (другая модель, другие шаги приёмки), а причину ищет вручную.

## Что нужно

- `crew_doctor` для каждого проекта сравнивает файл настроек в рабочей копии проекта с файлом на целевой ветке и при расхождении выдаёт предупреждение: какие ключи различаются и что действуют значения с ветки.
- Предупреждение не ошибка и не блокирует работу; в нём названы различающиеся ключи, а не весь файл.
- Предупреждение видно постоянно, пока расхождение есть: короткая строка в боковой панели окна и в сводке `/crew` (не только в `crew_doctor`); исчезает само, когда файл на ветке совпал с рабочей копией.
- Если файл не отслеживается или ветки нет — отдельная понятная строка, без падения.
- Один тест на случай «ключ есть в рабочей копии и нет на ветке» (красная проверка до правки), один — без расхождения (молчит).

## Что надо выяснить в разборе

- Где `crew_doctor` собирает проверки проекта (`settings.ts`, `settingsProblems`) и как там читается файл с ветки (`fileAt`).
- Какую рабочую копию считать «рабочей»: каталог проекта из реестра или каталог сессии.
- Где в боковой панели и в `/crew` разместить строку и как не засорять экран, когда расхождения нет.
