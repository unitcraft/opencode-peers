# Разбор задачи 029 (быстрый путь)

- Проверки проектов собирает `settingsProblems` (settings.ts); файл ветки читает `showCommitted` (`git show <ветка>:<файл>`). Сравнение — новый модуль `config-diverge.ts`, вызывается из `settingsProblems`.
- **Какую рабочую копию считать «рабочей».** Решение: файл настроек в папке настроек проекта из реестра (`Project.repo` + `Project.file`) — тот самый, что правит `crew_config set`. Довод: у проекта один файл настроек, и «каталог сессии» у разных сессий разный (worktree задач), а реестр однозначен.
- **Ветка для сравнения:** `origin/<ветка>`, затем локальная, как у `acceptance-file.ts`; сравнение по верхнеуровневым ключам, в предупреждении только названия ключей.
- **Постоянная строка.** Плагин окна реестра проектов не держит, поэтому папка проекта берётся из `settings-good/` (пишет чтение настроек без проблем); строка `⚠ настройки не на ветке: <ключи>` идёт в сводку `/crew` и боковую панель, пока файлы различаются, и пропадает сама. Проверка кешируется на 5 с (`CREW_HARNESS_DIVERGE_TTL_MS`).
- Нет файла/ветки/git — отдельная строка в `crew_doctor` (для ветки без файла уже была: «не закоммичен»), без падения; в постоянный показ такие строки не идут.
